# 부서 회신자료 자동취합기

여러 부서에서 받은 회신파일을 한 번에 올리면 **제출 부서를 자동으로 판별**하고,
**충주시 부서순서대로 정렬·취합**하여 통합 엑셀 파일 하나로 만들어 주는 프로그램입니다.

---

## 실행 방법 (사용자용)

1. `dist/부서회신자료_자동취합기.html` 파일 하나만 받으면 됩니다.
2. 파일을 **더블클릭**하면 Microsoft Edge 또는 Google Chrome 에서 바로 열립니다.
3. 설치·로그인·인터넷 연결이 필요 없습니다.

> 올린 파일은 사용자 PC의 브라우저 안에서만 처리되며 **어디에도 전송되지 않습니다.**
> 원본 파일은 **절대 수정하지 않습니다.**

### 사용 순서

| 단계 | 화면 | 하는 일 |
| --- | --- | --- |
| 1 | 파일 업로드 | 회신파일을 끌어놓거나 `파일 추가` 로 여러 개 선택 |
| 2 | 파일 분석 및 부서 판별 | `분석 시작` → 자동 판별 결과 확인, 틀린 부서만 직접 선택 |
| 3 | 취합 대상 및 서식 확인 | 기준 서식 확인, 서식이 다른 파일의 컬럼 맞추기 → `취합하기` |
| 4 | 취합 결과 미리보기 | 결과 확인, 부서 필터·검색, 미회신 부서 확인 |
| 5 | 결과 다운로드 | `결과 파일 만들기` → 자료 종류에 맞는 결과 파일을 내려받기 |

---

## 1. 프로그램 목적

지방자치단체에서 자주 발생하는 다음과 같은 업무에서, **수십 개의 부서 회신파일을
일일이 열어 복사·붙여넣기 하지 않도록** 하는 것이 목적입니다.

- 각 부서 실적자료 취합
- 현황자료 제출 취합
- 공공데이터 현행화 자료 취합
- 교육·행사 신청자료 취합
- 각종 평가자료 취합
- 시설·사업·대상자 현황 취합
- 정기·수시 자료제출 결과 취합

## 2. 주요 기능

- 여러 파일 한 번에 업로드 (파일 선택 · 다중 선택 · 끌어놓기)
- 파일별 개별 분석 — 한 파일에서 오류가 나도 전체 처리가 멈추지 않음
- 부서 자동판별 (파일명 → 대표 필드 → 문서 상단 → 사용자 직접 선택)
- 문서 안의 **실제 데이터표 자동 탐지** (안내문·담당자표와 구분)
- 여러 파일의 컬럼 구조를 비교해 **공통 서식(기준 스키마) 자동 판별**
- 서식이 다른 파일의 **컬럼 맞추기 화면**
- 동일 부서 복수 제출 표시 (자동 삭제하지 않음)
- 부서 마스터 순서대로 정렬 취합, 미확인 자료는 맨 아래
- **미회신 부서 자동 확인**
- 부서 관리 (추가·삭제·수정·별칭·사용여부·순서변경·드래그앤드롭·초기화·JSON 내보내기/가져오기)
- 결과 미리보기, 부서 필터, 키워드 검색, 파일 제외
- 자료 종류별 결과물 생성 — 회신현황 리포트(엑셀) + 온전한 취합본(엑셀 / 한글 / PDF)

## 3. 지원 파일 형식

| 형식 | 상태 | 설명 |
| --- | --- | --- |
| XLSX | 지원 | 모든 시트 조사, 병합 셀 처리 |
| XLSM | 지원 | XLSX 와 동일하게 처리 (매크로는 실행하지 않음) |
| CSV | 지원 | UTF-8 우선, 실패 시 EUC-KR(CP949) 로 다시 해석 |
| XLS | 지원 | 예전 엑셀 형식 |
| HWPX | 지원 | ZIP/XML 구조를 브라우저에서 직접 분석, 문단과 표를 읽음 |
| HWP 5.0 이상 | **일부 지원** | CFB(OLE) 컨테이너와 BodyText 레코드를 직접 읽어 문단·표 추출 |
| PDF | 지원 | 부서 판별용으로 본문 글자를 읽고, 원본 쪽을 그대로 이어붙여 취합 |

읽을 수 없는 파일은 성공한 것처럼 처리하지 않고 다음과 같이 구분해 표시합니다.

```
지원 / 일부 지원 / 확인 필요 / 지원하지 않는 형식 / 암호화 문서 / 손상된 문서 / 빈 파일
```

HWP/HWPX 를 읽는 목적은 **부서명 판별**과 **표 데이터 취합** 두 가지이며,
글꼴·색상·테두리 등 원본 한글서식을 복원하지는 않습니다.

## 4. 부서 자동판별 순서

```
1순위 파일명
  ↓ 실패
2순위 문서 안의 대표 필드 (부서명 / 담당부서 / 소관부서 / 제출부서 / 작성부서 / 담당과 …)
  ↓ 실패
3순위 문서 상단의 공식 부서명   → ⚠ 확인 권장
  ↓ 실패
4순위 사용자 직접 선택
```

- 판별 전에 확장자 제거, 앞뒤 공백 제거, 연속 공백 정리, 괄호·대괄호·언더바·하이픈 등
  구분문자 처리, 유니코드 정규화(NFKC)를 적용합니다.
- **부서명이 두 개 이상 발견되면 임의로 하나를 고르지 않고 `선택 필요` 로 남깁니다.**
- 이름이 비슷하다는 이유로 추정 매칭(fuzzy matching)을 하지 않습니다.
- **팀명으로 상위 부서를 추론하지 않습니다.** (예: `정보기획팀` 만 있으면 `부서 확인 필요`)
- 사용자가 직접 고른 부서가 항상 최종값입니다.

판별방법은 `파일명 / 대표 필드 / 문서 상단 / 사용자 지정 / 미확인`,
상태는 `✅ 확정 / ⚠ 확인 권장 / ❌ 선택 필요` 로 표시합니다.

## 5. 부서 관리 방법

`부서 관리` 탭에서 다음을 할 수 있습니다.

| 기능 | 설명 |
| --- | --- |
| 부서 추가 / 삭제 / 부서명 수정 | 표에서 바로 편집 |
| 별칭 | 쉼표로 구분해 여러 개 입력 (예: `정보과, 전산과`) |
| 사용 여부 | 끄면 취합·미회신 집계 대상에서 빠짐 |
| 순서 변경 | `▲` `▼` 버튼 또는 행 끌어놓기 |
| 기본 부서목록으로 초기화 | 프로그램에 들어있는 충주시 부서목록으로 되돌림 |
| 부서설정 내보내기 / 가져오기 | JSON 파일로 저장·복원 (다른 PC 로 옮길 때 사용) |

- **저장**을 눌러야 이 브라우저(`localStorage`)에 보관되어 다음 실행에도 유지됩니다.
- 저장하는 내용은 **부서명·순서·별칭·사용여부·프로그램 설정뿐**입니다.
  업로드한 회신자료의 내용이나 개인정보는 저장하지 않습니다.
- 조직개편이 있어도 HTML 파일을 고치지 않고 이 화면에서 대응할 수 있습니다.

## 6. 회신자료 취합 방법

### 데이터표 자동 탐지

- **엑셀** — 모든 시트를 조사해 머리글 후보와 이어지는 데이터 영역을 찾습니다.
  병합 셀은 좌측 상단 값을 병합 범위에 채워 판단하고, 상단 안내영역(제목·부서정보·담당자)과
  실제 데이터표를 구분합니다. 표 중간의 빈 행 1줄은 표의 일부로 봅니다.
  데이터가 가장 많은 표를 기본으로 선택하며, 사용자가 다른 시트/표를 고를 수 있습니다.
- **HWP/HWPX** — 문서 안의 표를 모두 찾아 행·열 수를 비교하고,
  제목·작성자 정보용 작은 표와 실제 회신 데이터표를 구분합니다.

### 공통 서식(기준 스키마) 판별

업로드 순서로 첫 번째 파일을 기준으로 삼지 않습니다.
각 파일에서 찾은 표의 컬럼 구조를 비교해 **가장 많은 파일이 공통으로 쓰는 구조**를
기준 서식으로 정합니다. 컬럼 순서만 다른 경우는 같은 서식으로 봅니다.

- 컬럼명 비교 전 앞뒤 공백 제거, 연속 공백 정리, 줄바꿈 제거, 유니코드 정규화를 적용합니다.
- **정확히 같은 컬럼명(공백·줄바꿈 차이 포함)만 자동 매칭합니다.**
  `주소 ↔ 소재지`, `관리번호 ↔ 일련번호` 처럼 의미가 비슷하다는 이유로 임의 매핑하지 않고,
  단계 3의 컬럼 맞추기 화면에서 사용자가 지정하도록 합니다.

### 취합 규칙

- 머리글은 결과에 **한 번만** 생성되며, 각 파일의 머리글 행이 데이터로 섞이지 않습니다.
- 맨 앞에 관리 컬럼 `부서명`, `원본파일명`, `원본시트/표` 를 추가합니다.
- 완전히 빈 행은 제외합니다. 일부 값만 비어 있는 행은 그대로 둡니다.
- **부서 마스터의 순서(order)** 로 정렬하며, 같은 부서 안에서는 원본 파일 순서와 행 순서를 유지합니다.
- 부서를 확인하지 못한 자료는 `미확인` 으로 표시되어 맨 아래에 옵니다.
- 같은 부서에서 두 개 이상 제출한 경우 자동으로 지우지 않고 `⚠ 동일 부서 복수 회신` 으로 알립니다.

## 7. 결과 파일 구성

결과는 **두 가지**로 나뉩니다. 올린 자료의 종류에 따라 만들어지는 파일이 달라집니다.

### (1) 회신현황 리포트 — 항상 엑셀

`부서회신자료_통합결과_YYYYMMDD.xlsx` (실행일 기준)

| 시트 | 내용 |
| --- | --- |
| 통합자료 | `부서명 · 원본파일명 · 원본시트/표 · (기준 서식 컬럼들)` 을 부서순서대로 |
| 회신현황 | `순서 · 부서명 · 사용여부 · 회신여부 · 파일수 · 취합건수` — **미회신 부서 포함** |
| 파일별처리결과 | `파일명 · 판별부서 · 판별방법 · 사용여부 · 선택 데이터표 · 취합건수 · 상태` |
| 오류및경고 | `파일명 · 구분 · 내용` (형식 / 부서 / 서식 / 중복 / 자료) |
| 취합순서 | 한글·PDF 취합본이 있을 때만 생성. 어느 부분이 어느 부서인지 (PDF 는 쪽 번호까지) |

### (2) 온전한 취합본 — 자료 종류에 맞춰

| 올린 자료 | 만들어지는 취합본 |
| --- | --- |
| 엑셀 · CSV | 위 엑셀의 **통합자료** 시트 (기준 서식으로 합친 표) |
| 한글 (hwp/hwpx) | `부서회신자료_한글취합본_YYYYMMDD.hwpx` + `부서회신자료_한글원본_YYYYMMDD.zip` |
| PDF | `부서회신자료_PDF취합본_YYYYMMDD.pdf` |

- **한글취합본(hwpx)** — 각 문서의 문단과 표를 부서순서대로 이어붙여 새로 만든 한글 파일입니다.
  문서마다 `■ 부서명 — 원본파일명` 제목을 붙이고 쪽을 나눕니다. 원본 서식은 옮기지 않습니다.
- **한글원본 묶음(zip)** — 원본 한글파일을 `01_부서명_원본파일명` 형태로 부서순서대로 담고,
  `00_취합순서.txt` 안내를 함께 넣습니다. **원본이 그대로 보존**되므로 서식이 필요하거나
  취합본이 열리지 않을 때 사용합니다.
- **PDF 취합본** — 원본 쪽을 부서순서대로 이어붙입니다. 원본 쪽 자체를 옮기므로 내용이 그대로 유지됩니다.
  어느 쪽이 어느 부서인지는 리포트 엑셀의 `취합순서` 시트에서 확인합니다.

## 8. 오프라인 처리 및 보안

- 서버 없음, 데이터베이스 없음, Python 백엔드 없음
- 생성형 AI API 없음, 외부 API 호출 없음, 외부 CDN 없음
- 업로드 파일을 외부로 전송하지 않음 — 모든 분석은 브라우저 메모리에서만 수행
- 원본 파일을 수정하지 않음
- 원문 데이터를 `localStorage` 에 저장하지 않음 (부서 설정만 저장)
- 분석서비스·통계수집 기능 없음
- HTML 에 CSP(`default-src 'none'; connect-src 'none'` 등)를 적용해 외부 연결을 차단
- SheetJS / JSZip 은 `vendor/` 에 로컬 포함되어 최종 HTML 안에 함께 들어갑니다
  (CDN URL 이 남아 있지 않은지 빌드 시 자동 검사)

AI 는 이 프로그램을 **개발하는 과정에서만** 사용했으며, 완성된 HTML 실행 중에는
어떠한 AI 기능도 동작하지 않습니다.

## 9. 알려진 제한사항

- **HWP(바이너리)는 일부 지원입니다.** 문단 텍스트와 표를 추출하지만
  다음은 읽지 않습니다: 배포용(문서 보호) 문서, 암호 설정 문서.
  중첩이 복잡한 표는 구조가 정확하지 않을 수 있으며, 표를 찾지 못하면
  `이 파일에서 취합할 표를 찾지 못했습니다.` 로 안내합니다.
  (HWP 는 자동 생성한 샘플 문서로 검증했으며, 실제 한/글로 저장한 문서 전체를
  검증하지는 못했습니다. 중요한 자료는 HWPX 나 엑셀로 받는 것을 권장합니다.)
- **한글취합본(HWPX)은 이 프로그램이 새로 만들어 내는 파일입니다.** 개발 환경에 한/글이 없어
  실제 한/글에서 열리는지는 검증하지 못했고, HWPX 구조 검사와 되읽기 검증까지만 마쳤습니다.
  이 때문에 **원본 한글파일 묶음(zip)을 항상 함께 제공**합니다. 취합본이 열리지 않으면 원본 묶음을 사용하세요.
  또한 취합본에는 글꼴·색상·테두리 등 원본 서식이 옮겨지지 않습니다.
- **PDF 는 표를 뽑지 않습니다.** PDF 에서 표 구조를 신뢰할 수 있게 복원할 수 없기 때문에,
  본문 글자는 부서 판별에만 쓰고 자료 자체는 원본 쪽을 그대로 이어붙여 취합합니다.
  따라서 PDF 자료는 리포트 엑셀의 `통합자료` 시트에 들어가지 않습니다.
- 글자가 없는 **스캔(이미지) PDF** 는 부서를 자동 판별하지 못합니다. 파일명으로도 찾지 못하면
  직접 선택해야 하며, 쪽 자체는 정상적으로 취합됩니다.
- 암호화된 XLSX/HWPX/HWP/PDF 는 복호화하지 않고 `암호화 문서` 로 표시합니다.
- 컬럼명이 서로 다른 파일은 자동 매칭하지 않습니다. 단계 3에서 직접 맞춰야 합니다.
- 부서 판별은 `사용 여부 = 사용` 인 부서와 그 별칭만을 대상으로 합니다.
- 셀 서식(글꼴·색상·테두리)은 결과에 반영하지 않습니다. 값만 취합합니다.
- 한 시트당 최대 50,000행 · 200열까지 읽습니다.
- 결과 미리보기 화면에는 앞 300행만 표시합니다(다운로드 파일에는 전체 포함).
- 브라우저 저장소를 쓸 수 없는 환경(시크릿 모드 등)에서는 부서 설정이 저장되지 않고
  현재 창에서만 적용됩니다.

브라우저에서는 `<script>`, Node 에서는 `require` 로 동일하게 읽힙니다.

## 11. 테스트 방법

```bash
npm install          # 개발용 라이브러리 설치 (SheetJS, JSZip, Playwright)
npm run build        # 단일 HTML 빌드
npm test             # 핵심 기능 자동 테스트 (62건)
npm run test:browser # 실제 Chromium 에서 전체 흐름 확인
npm run verify       # 위 세 가지를 한 번에
```

`npm test` 는 테스트용 회신파일(XLSX / CSV / HWPX / HWP)을 그 자리에서 만들어
다음을 검증합니다.

- 부서: 파일명(공식명·별칭·없음·두 개 동시), 대표 필드, 문서 상단, 미확인,
  사용자 직접 변경, 팀명 자동추론 금지
- 자료: 정상 XLSX, 다중 시트, 머리글이 1행이 아닌 경우, 위쪽 부서정보 + 아래쪽 데이터표,
  HWPX, 복수 표 HWPX, HWP, 암호화 문서, 손상 파일, 빈 행, 컬럼 순서 차이,
  컬럼명 공백·줄바꿈 차이, 컬럼 누락, 동일 부서 복수 파일
- PDF: 본문에서 부서 찾기, 표를 추측하지 않음, 쪽 순서가 부서순서를 따르는지, 손상 PDF 구분
- 취합본: HWPX 생성 후 되읽기, HWPX 필수 구성요소와 XML 형식, 원본 ZIP 의 바이트 일치,
  자료 종류별 결과물 구성, 취합순서 시트
- 결과: 부서순서 정렬, 업로드 순서 무관 동일 결과, 반복 머리글 제거, 미회신 부서,
  부서별 파일수·행수, 미확인 표시, XLSX 다운로드, 한글 파일명·데이터
- 오프라인: 배포본에 외부 참조 없음, 소스에 네트워크 호출 없음, 원문 미저장

`npm run test:browser` 는 실제 Chromium 에서 배포본 HTML 을 열어
한글 파일명 파일(엑셀·CSV·HWPX·HWP·PDF)을 끌어놓기로 올리고 분석 → 취합 →
결과 파일 4종 생성·다운로드까지 수행합니다. 내려받은 엑셀·PDF·HWPX·ZIP 을 각각 다시 열어
내용을 확인하고, **외부 네트워크 요청이 0건**인지와 콘솔 오류가 없는지 검사합니다.

## 12. 최종 단일 HTML 빌드 방법

```bash
npm install
npm run vendor       # (선택) node_modules 의 라이브러리를 vendor/ 로 복사
npm run departments  # (선택) data/충주시_부서순서.xlsx 로 기본 부서목록 재생성
npm run build        # dist/부서회신자료_자동취합기.html 생성
```

`build.js` 는 `index.html` 이 참조하는 CSS/JS 를 순서대로 HTML 안에 넣고,
인라인되지 않은 외부 참조나 CDN URL 이 남아 있으면 빌드를 실패시킵니다.

## 13. 기본 부서목록 (충주시)

`data/충주시_부서순서.xlsx` 를 실제로 읽어 생성했습니다.

- 시트명: `충주시 직제순서`
- 1행: 병합된 제목 `충주시 행정기구 직제순서 (2026.1.1. 시행 기준)` (A1:D1)
- 2행: 머리글 `순번 | 소속(국/실) | 부서명(과) | 비고`
- 3~77행: 부서 데이터 (빈 행 없음, `비고` 열은 비어 있음)
- 엑셀에서 읽은 부서 **75개**, 순서는 원본 엑셀의 순번을 그대로 사용
  (`1 홍보담당관` … `6 정보통신과` … `75 목행용탄동`)
- 여기에 **`76 의회사무국`** 을 추가로 넣었습니다(첨부 엑셀에는 없는 부서로, 요청에 따라 추가).
  `build/generate-department-master.js` 의 추가 목록으로 관리하므로 부서목록을 다시 만들어도 유지됩니다.
- 따라서 기본 부서는 **전체 76개** 입니다.
- `소속(국/실)` 값은 참고 정보로 함께 보관하며, 취합 단위는 **부서(과)까지**입니다.
  팀 단위는 관리하지 않습니다.

부서목록을 바꾸려면 HTML 을 고치지 말고 `부서 관리` 화면에서 수정한 뒤 저장하세요.
